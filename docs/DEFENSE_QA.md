# שאלות ותשובות מוכנות להגנה בזום

## מה הבעיה שהפרויקט פותר?
הפרויקט פותר בעיה של חוסר סדר וחוסר אחידות בתכנון אירוע עם בובות מתנפחות. הוא עוזר לבחור חבילה, לבדוק פרטים לוגיסטיים ולתת תשובות מהירות ומבוססות מידע.

## למה בחרתם דווקא בתחום האירועים?
זה תחום שיש בו צורך אמיתי בשיחה עם לקוחות, בדיקת פרטים, תמחור, תיאום לוגיסטי ותוכן ויזואלי. לכן הוא מתאים מאוד לשילוב של שיחה, תמונה, RAG ושמע.

## איך מימשתם Conversational AI?
ב־`src/openai_utils.py` יש פונקציה `chat_with_ai` ששולחת את שאלת המשתמש ל־OpenAI Responses API ומחזירה תשובה בעברית לפי system prompt מקצועי.

## איך מימשתם RAG?
ב־`src/rag.py` המערכת קוראת קבצים מתוך `knowledge_base`, מחלקת אותם למקטעים, יוצרת embedding לכל מקטע, שומרת אותם ב־ChromaDB, ובזמן שאלה שולפת את המקטעים הכי רלוונטיים.

## למה צריך ChromaDB?
ChromaDB משמש בתור vector database. הוא שומר את ה־embeddings ומאפשר למצוא את הקטעים הקרובים ביותר לשאלה של המשתמש.

## איך מימשתם מולטימודליות?
בלשונית ניתוח תמונה המשתמש מעלה תמונה. הקובץ מומר ל־Base64 data URL ונשלח ל־OpenAI Responses API עם `input_image`. המודל מחזיר ניתוח של התמונה בהקשר של אירוע.

## מה היכולת הנוספת שבחרתם?
בחרנו Text-to-Speech. אחרי שהעוזר מחזיר תשובה, אפשר ליצור ממנה קובץ MP3 בעזרת OpenAI Audio Speech API.

## מה היתרון של RAG לעומת תשובה רגילה של מודל?
בלי RAG המודל עונה מידע כללי. עם RAG הוא מקבל מידע פנימי של העסק, כמו חבילות, מחירים, מדיניות מקדמה וצ'ק ליסט תפעולי, ולכן התשובה מותאמת יותר לפרויקט.

## איך אפשר להרחיב את הפרויקט בעתיד?
אפשר להוסיף התחברות ליומן זמינות, הצעות מחיר אוטומטיות, שמירת לקוחות, תמיכה בקבצי PDF נוספים לבסיס הידע, חיבור לוואטסאפ, או יצירת סיכום ללקוח אחרי שיחה.
